# 디스크 캐시 정리와 공간 부족 방지

2026-11-06 점검에서 루트 파일시스템의 가용 공간이 **582,930,432바이트(약 0.54GiB)**였다. 재생성 가능한 캐시와 검토한 미사용 빌드 이미지를 정리한 뒤 **7,557,554,176바이트(약 7.04GiB)**로 늘었다. 가용 공간은 다른 작업의 쓰기에 따라 계속 변한다.

## 이번에 정리한 항목

- `npm cache clean --force`: 사용자 npm 다운로드 캐시 약 5.1GiB. 설치된 `node_modules`는 보존했다.
- `docker builder prune --all --force --filter until=168h --keep-storage 4GB`, 이어서 `docker builder prune --all --force --keep-storage 4GB`: 사용하지 않는 빌드 캐시 정리. 두 번째 명령이 보고한 회수량은 1.275GB였다. `keep-storage`는 정리 가능한 캐시의 보존 예산이며 이미지가 공유하는 레이어 때문에 전체 표시 용량이 4GB보다 클 수 있다.
- `python3 -m pip cache purge`: 다운로드·wheel 캐시 528개 파일. 설치된 Python 가상환경은 보존했다.
- 태그가 없고 어떤 컨테이너도 사용하지 않으며 기록된 롤백 설정에도 없는 빌드 이미지 `30a57b7587b5`만 검토 후 `docker image rm`으로 제거했다. 강제 삭제는 사용하지 않았다.

사용자 데이터, PostgreSQL·Redis·Kafka 볼륨, 복구 백업, 환경변수·비밀키, 원본 녹화, 최종 MP4/SRT, 모델 가중치, 설치된 의존성, Playwright 브라우저, 당시 실행 중이던 Rust 테스트의 빌드 폴더와 롤백용 이미지 태그는 보존했다. 컨테이너를 재시작하지 않았다.

APT 다운로드 캐시 약 1.6GiB도 확인했으나 `sudo -n apt-get clean`이 관리자 인증을 요구해 정리하지 못했다. 패키지 삭제나 관리자 권한 우회는 하지 않았다. 자동 전체 이미지/볼륨 정리도 등록하지 않았다.

## 추가한 보호 장치

`infra/ci/check-space.sh`는 파일을 지우지 않고 가용 공간만 확인한다. 기본 하한은 **4096MiB**이며 `CI_MIN_FREE_MIB`로 양의 정수 하한을 지정할 수 있다. 검사 파일시스템은 프로젝트 경로이고 `CI_DISK_PATH`로 바꿀 수 있다. Docker 데이터가 별도 파일시스템이면 그 위치도 별도로 확인해야 한다.

- `infra/ci/run.sh`가 검증 시작 전과 배포 준비 전에 검사한다.
- 직접 실행한 `infra/ci/check.sh backend`도 빌드 파일 생성 전에 검사한다.
- 공간 부족은 종료 코드 77과 `status=deferred`로 기록되어 Docker 실행 전에 중단된다.
- 공간 조회 실패·잘못된 설정은 검사 통과로 처리하지 않는다.
- 이 장치는 이미 가득 찬 디스크에서 작업을 시작하는 것을 막는다. 빌드 중 다른 프로세스의 쓰기를 제한하거나 콜드 빌드 용량을 예약하지는 않는다. 운영 여유는 [사양 측정 문서](hardware-requirements.md)의 더 큰 예산을 따른다.
- 적용 대상은 이 저장소의 스크립트이다. 다른 체크아웃을 실행하는 기존 서비스는 해당 체크아웃도 업데이트해야 같은 보호를 받는다.

## 검증

공간 부족과 검증 도중 공간이 감소하는 두 상황을 먼저 모의 재현해 기존 스크립트에서 회귀 검사가 실패함을 확인했다. 수정 후 공간 경계·설정 오류·조회 실패 8개 시나리오, 배포·롤백 10개 시나리오, 기존 Python 검사 258개와 학교 장면 일관성 검사가 통과했다. 실제 CI 래퍼에 현재 공간보다 큰 하한을 주었을 때 검증·Docker 실행에 진입하지 않고 종료 77, `deferred` 결과를 반환하는 것도 확인했다.

공개 서비스 HTTP smoke와 PostgreSQL·Redis 준비 상태를 다시 검사했다. 세부 명령 결과와 점검 화면은 로컬 `runtime/qa/maintenance-20261106/`에 보관한다.

## 재발 방지 운영 원칙

캐시 정리는 작업이 없을 때 명시적으로 실행한다. 우선 다운로드 캐시와 사용하지 않는 빌드 캐시를 구분하고, 실행 이미지·롤백 태그·원본·데이터 볼륨을 정리 대상으로 섞지 않는다. 새 빌드나 긴 영상 보관이 예정돼 있으면 현재 약 7GiB보다 더 큰 여유를 확보한다. 자동 `docker system prune --volumes`나 전체 사용자 캐시 디렉터리 삭제는 사용하지 않는다.
